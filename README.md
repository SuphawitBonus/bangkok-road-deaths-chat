# Bangkok Road Deaths — Chat with the data

ถามเป็นภาษาไทยหรืออังกฤษว่าอยากรู้อะไรเกี่ยวกับผู้เสียชีวิตจากอุบัติเหตุทางถนนในกรุงเทพฯ
ระบบให้ AI เขียน SQL ไปค้นข้อมูลจริง แล้วตอบเป็นตัวเลขพร้อมกราฟ โดย**แสดง SQL ที่ใช้** และ
**บอกข้อควรระวังของข้อมูล** ทุกครั้ง

ฐานข้อมูลมาจากชุดข้อมูลเปิดของกรมควบคุมโรคผ่าน [data.go.th](https://data.go.th/dataset/rtddi)
จำนวน 12,146 ราย ตั้งแต่ พ.ศ. 2554–2569

> **สถานะ: สัปดาห์ที่ 1 จาก 4** — ตอนนี้มีเฉพาะชั้นข้อมูล ความปลอดภัยของการรัน SQL และโครงชุดทดสอบ
> ยังไม่มีส่วน AI และหน้าเว็บ

## แผน 4 สัปดาห์

| สัปดาห์ | ขอบเขต | สถานะ |
| --- | --- | --- |
| 1 | ข้อมูลเข้า Postgres, ชั้นความปลอดภัยของ SQL, โครง eval | ✅ เสร็จ |
| 2 | ต่อ LLM เขียน SQL จากคำถาม + วัดผลด้วย eval 50 ข้อ | ⬜ |
| 3 | หน้าเว็บ Next.js แสดงคำตอบ กราฟ และ SQL ที่ใช้ | ⬜ |
| 4 | deploy (Neon + Vercel), ขัดเกลา, เขียนเอกสาร | ⬜ |

## เริ่มใช้งาน

ต้องมี Docker Desktop และ Node.js 20.6 ขึ้นไป

```bash
npm install
cp .env.example .env        # แล้วเปิดไฟล์ไปตั้งรหัสผ่านทั้งสองตัว
npm run db:up               # ยก Postgres ขึ้นใน Docker
npm run db:setup            # สร้าง schema + role แล้วโหลดข้อมูล (รันซ้ำได้)
npm test                    # ชุดทดสอบตัวตรวจ SQL (74 ข้อ ไม่ต้องใช้ฐานข้อมูล)
npm run db:check            # ยิงคำสั่งอันตรายด้วย role ของ AI เพื่อพิสูจน์ชั้นฐานข้อมูล
npm run evals:verify        # ตรวจว่าเฉลยในชุดคำถามตรงกับฐานข้อมูลจริง
npm run docs:schema         # สร้าง docs/data-dictionary.md จาก COMMENT ON ในฐานข้อมูล
```

> พอร์ตเริ่มต้นคือ 5435 ไม่ใช่ 5432 เพราะพอร์ตมาตรฐานมักถูกโปรเจกต์อื่นใช้อยู่แล้ว
> เปลี่ยนได้ที่ `POSTGRES_PORT` ใน `.env`

## โครงสร้าง

| โฟลเดอร์ | คืออะไร |
| --- | --- |
| `db/` | ไฟล์ SQL ของ schema, view `deaths` พร้อม `COMMENT ON` และ role สำหรับ AI |
| `src/sql-guard.ts` | ตัวตรวจ SQL ที่ AI เขียน ก่อนส่งเข้า DB |
| `src/scripts/` | สคริปต์ migrate, load ข้อมูล, ตรวจเฉลยของ eval |
| `data/` | ฝั่งข้อมูลที่เป็น Python — สคริปต์ดึงข้อมูลจาก data.go.th และไฟล์ CSV ดิบ |
| `evals/` | ชุดคำถามทดสอบพร้อมเฉลย (`questions.jsonl`) |
| `tests/` | ชุดทดสอบ (vitest) |
| `docs/` | [ความปลอดภัย](docs/security.md) · [พจนานุกรมข้อมูล](docs/data-dictionary.md) · [ชุดทดสอบ](docs/evals.md) |

## หลักการที่ยึดไว้

1. **SQL ที่ AI เขียนถือว่าไม่น่าเชื่อถือเสมอ** จึงมีสองชั้นป้องกันที่ทำงานเป็นอิสระต่อกัน
   ชั้นฐานข้อมูลเป็นชั้นหลัก ชั้นโค้ดเป็นชั้นเสริม — รายละเอียดใน [docs/security.md](docs/security.md)
2. **AI เห็นได้แค่ view `deaths` ที่ทำความสะอาดแล้ว** ไม่เห็นตารางดิบ ไม่เห็น schema อื่น
3. **ข้อจำกัดของข้อมูลเขียนไว้ใน `COMMENT ON` ของทุกคอลัมน์** เพื่อให้สัปดาห์ที่ 2 ส่งให้ AI อ่าน
   ได้จากฐานข้อมูลโดยตรง ไม่ต้องมี prompt ที่หลุดจากความจริงของ schema
4. **คำถามที่ข้อมูลตอบไม่ได้ ต้องปฏิเสธ** ไม่ใช่เดาตัวเลข — จึงมี eval ประเภท `unanswerable` ด้วย

## ที่มาข้อมูล

ระบบบูรณาการข้อมูลการตายจากอุบัติเหตุทางถนน (3 ฐาน) กรมควบคุมโรค กระทรวงสาธารณสุข
เผยแพร่ผ่าน data.go.th ภายใต้เงื่อนไขข้อมูลเปิดภาครัฐ
