# ฝั่งข้อมูล (Python)

โปรเจกต์หลักเป็น TypeScript เพราะสัปดาห์ที่ 3 จะเป็น Next.js แต่สคริปต์ดึงข้อมูล
แยกไว้เป็น Python ในโฟลเดอร์นี้ เหตุผลคือมันเป็นงานคนละจังหวะกับแอป: รันนาน ๆ ครั้ง
ตอนที่ data.go.th ออกข้อมูลชุดใหม่ ไม่ได้รันตอนผู้ใช้เปิดเว็บ และโค้ดชุดนี้
ยกมาจากงานวิเคราะห์เดิมที่พิสูจน์แล้วว่าใช้ได้กับความแปลกของข้อมูลชุดนี้

| ไฟล์ | คืออะไร |
| --- | --- |
| `fetch_data.py` | ดึงข้อมูลทุกปีจาก data.go.th (CKAN) มารวมเป็น CSV ไฟล์เดียว |
| `bangkok-road-deaths.csv` | ผลลัพธ์ที่ดึงมาแล้ว 12,146 แถว commit ไว้เพื่อให้ตั้งโปรเจกต์ได้โดยไม่ต้องต่อเน็ต |

## ดึงข้อมูลใหม่

```bash
python data/fetch_data.py
```

> ต้องรันจากเครือข่ายที่ data.go.th ตอบ — ทดสอบแล้วว่าจากในไทยใช้ได้ปกติ
> แต่คำขอที่ออกจาก IP ของ AWS ถูกปฏิเสธภายในเสี้ยววินาที

ใช้แค่ไลบรารีมาตรฐานของ Python (`urllib`, `csv`, `json`) ไม่ต้องลงอะไรเพิ่ม

หลังดึงเสร็จต้องโหลดเข้าฐานข้อมูลใหม่

```bash
npm run db:load
```

## ความแปลกของข้อมูลต้นทางที่สคริปต์นี้รับมือไว้

- **ชื่อคอลัมน์เปลี่ยนตามปี** ปี 2568 ใช้ `จ.ที่เสียชีวิต` ส่วน 2569 ใช้ `Dead_Prov`
  สคริปต์จึงไล่ลองชื่อที่เป็นไปได้ทีละตัวแทนที่จะยึดชื่อเดียว
- **`package_show` ล่มบ่อย** จึงมี resource id สำรองที่รู้ล่วงหน้าไว้ใช้เมื่อเรียกไม่ได้
- **ข้อมูลแยกไฟล์ตามปี** สคริปต์วนดึงทุกปีแล้วรวมเป็นไฟล์เดียว พร้อมคอลัมน์ `year_th` กำกับ

ส่วนการทำความสะอาดค่า (พิกัดสลับคอลัมน์ อายุ 149 ปี ฯลฯ) **ไม่ได้ทำที่นี่**
แต่ทำใน SQL ของ view `deaths` ดู `db/02_view.sql` เหตุผลอยู่ในหัวคอมเมนต์ของไฟล์นั้น
